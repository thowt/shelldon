# Publishing: F-Droid and IzzyOnDroid

Status 2026-11-16. Written from F-Droid's published inclusion policy and the reproducible-builds
article (links at the end). Nothing here has been submitted yet.

## Decision

**IzzyOnDroid first, official F-Droid later.** IzzyOnDroid takes the APK we build and sign ourselves,
so one signature works everywhere (GitHub, IzzyOnDroid, the phone). Official F-Droid builds from
source and, unless the build is reproducible, signs with its own key, so an APK from another source
cannot update over it. Official F-Droid waits until the Mosh question below is solved.

## What F-Droid requires, and where Shelldon stands

| Rule | Status |
| --- | --- |
| Everything FLOSS, dependencies included, buildable with FLOSS tools only (no Oracle JDK) | `oss` flavour only, no Play Services. Builds use OpenJDK (Temurin). To re-check when dependencies change. |
| Prebuilt binaries only from trusted sources (Debian, Maven Central and similar) and freely licensed | **Open.** The Mosh module downloads `libmoshexec.so` and terminfo from `connectbot/mosh4android` GitHub releases during the build (`build-logic` `PrepareMoshArtifacts`). Expect F-Droid to refuse that. Options: build Mosh from source in the build, or an F-Droid build without the Mosh module. Since round 2 the four archives are pinned by SHA-256 in `gradle/mosh4android.sha256` (the build fails on a mismatch); that protects against a swapped download, it does not make the binary reviewed source. |
| A fork needs its own application id, name and icon | Done: `io.github.thowt.shelldon`, "Shelldon SSH", own icon. |
| No trademark or copyright infringement; every asset needs a valid licence | **Open.** Name and trademark check, and the licence position of the AI-generated icon (see PLAN.md "Open items"). |
| Donation links must be verified by the upstream author | Upstream's links were removed. |
| No downloading of executables without explicit consent | Nothing is downloaded at run time. |
| No tracking, ads or analytics | None; `allowBackup` is false (it was still true in the manifest until round 2, although this table said otherwise). |
| Libraries from Maven Central, FLOSS | Round 2 added BouncyCastle `bcprov-jdk18on` (Argon2id for the vault): MIT-style licence, plain Maven dependency, nothing extra for F-Droid. |
| Source tag per release, `versionCode` from the repo | Needs our own tags in `thowt/shelldon` (the cloud session cannot push tags, the owner pushes them). See "Versions". |
| Metadata in the source repo | `app/src/oss/fastlane/metadata/android/en-US/` (title, short description under 80 characters, full description). Screenshots and `images/icon.png` still to add. |
| Changelog per release | `changelogs/<versionCode>.txt`, at most 500 characters. Written when a release is cut, because the file name is the version code. |

F-Droid's "all donation links", "no unverified network services" and "applications must be useful"
rules need nothing from us today. Sync will only talk to servers the user configures; if it is ever
tied to a specific proprietary service, F-Droid would add an anti-feature label.

## Versions

- `versionName` is `shelldon.version` from `gradle.properties` (`0.1.0`), plus `+<commits since the anchor tag>`
  on builds that are not at a tag. That string is what Settings shows.
- `versionCode` still comes from the upstream anchor tag `v1.12.0-alpha` plus the commit count
  (`AndroidVersions`). It only has to grow, and it does. Before the first public release the owner
  pushes a `v0.1.0` tag and we switch the anchor to our own tags, because F-Droid checks out a tag.

## Signing

- The internal key (`CN=Shelldon SSH internal builds`) is for test builds. Public releases get a
  separate production key, generated by the owner, stored offline with a backup, never in the repo.
- IzzyOnDroid can pin the allowed signing certificate (`AllowedAPKSigningKeys` is the F-Droid
  equivalent), which protects users if the repo is ever compromised. Keep the production key's
  SHA-256 in `docs/SIGNING.md` once it exists.

## Checklist before the first public release

1. Repo goes public, licence and NOTICE re-read, name and trademark check done.
2. Icon licence position settled and stated in the repo (who holds the rights, which licence).
3. Production signing key created and backed up.
4. `v0.1.0` tag pushed, anchor switched, changelog file for that version code added.
5. Screenshots added under `fastlane/metadata/android/en-US/images/phoneScreenshots/`.
6. IzzyOnDroid: request inclusion with the repository link.
7. Official F-Droid: Request for Packaging issue plus a merge request with the build metadata to
   `fdroiddata`, after the Mosh question is answered.
